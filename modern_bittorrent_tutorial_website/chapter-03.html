3. Bits, bytes, hexadecimal, encodings, and Buffer

3.1 Why this chapter matters

A BitTorrent client spends much of its time converting between meaningful values and exact byte layouts. Buffer is the Node.js type used for those bytes. Understanding it removes most of the mystery from tracker and peer messages.

3.2 Bits and bytes

A bit is one binary digit: 0 or 1. Eight bits make one byte. A byte can represent 256 different patterns, from 00000000 to 11111111, which are the decimal values 0 through 255.

BinaryDecimalHexadecimalComment
00000000000All bits off.
00000001101The lowest bit is on.
00001010100AHex uses A for decimal 10.
011111111277FLargest positive signed 8-bit value.
11111111255 unsigned / -1 signedFFThe meaning depends on signedness.

3.3 Why hexadecimal is used

Binary is accurate but long. Hexadecimal groups each four bits into one character, so one byte is always shown by two hex characters. The byte 11110000 becomes F0. Network debugging tools commonly show packets in hex because offsets and byte boundaries remain easy to see.

3.4 Text encodings are rules, not decorations

A string such as hello is abstract text. To send it through a socket, it must be encoded as bytes. UTF-8 is the normal text encoding in Node.js. ASCII is a smaller historical character set whose common English characters have the same byte values as UTF-8.

Text and bytes

JavaScript
import { Buffer } from 'node:buffer';

const text = Buffer.from('hello', 'utf8');
console.log(text);                 // <Buffer 68 65 6c 6c 6f>
console.log(text.toString('hex')); // 68656c6c6f
console.log(text.toString('utf8'));// hello

The bytes 68 65 6c 6c 6f are hexadecimal values. They are not the characters six, eight, six, five, and so on. The console uses hex merely to display the raw bytes.

3.5 Buffer.alloc, Buffer.from, and Buffer.allocUnsafe

MethodUse it whenSafety
Buffer.alloc(length)You know how many bytes are required and want them initially set to zero.Safest default for protocol messages.
Buffer.from(value)You already have text, an array of byte values, another Buffer, or compatible data.Copies or encodes existing data.
Buffer.allocUnsafe(length)You will immediately overwrite every byte and need maximum allocation speed.May expose old memory content until overwritten. Avoid while learning.

3.6 Buffers are fixed length

Write a 32-bit integer

JavaScript
const buffer = Buffer.alloc(4);
buffer.writeUInt32BE(1000, 0);
console.log(buffer); // <Buffer 00 00 03 e8>

Buffer.alloc(4) creates exactly four bytes. It cannot grow. writeUInt32BE writes an unsigned 32-bit integer in big-endian order starting at offset 0. The value 1000 is 0x000003E8, so the four bytes are 00 00 03 E8.

3.7 Signed and unsigned integers

Unsigned values cannot be negative. A 16-bit unsigned integer ranges from 0 to 65,535. Signed formats reserve one bit pattern range for negative values. The UDP announce request uses a signed 32-bit field for num_want because -1 means use the tracker default.

The same bits, two interpretations

JavaScript
const b = Buffer.alloc(4);
b.writeInt32BE(-1, 0);
console.log(b.toString('hex')); // ffffffff
console.log(b.readInt32BE(0));  // -1
console.log(b.readUInt32BE(0)); // 4294967295

3.8 Big-endian and little-endian

Endianness is the order in which a multi-byte number is stored. Network protocols commonly use big-endian, sometimes called network byte order. Big-endian writes the most significant byte first. BitTorrent tracker and peer integers in this guide are big-endian.

Same number, different byte order

JavaScript
const b = Buffer.alloc(4);
b.writeUInt32BE(0x12345678, 0);
console.log(b.toString('hex')); // 12345678

b.writeUInt32LE(0x12345678, 0);
console.log(b.toString('hex')); // 78563412

3.9 Offsets

An offset is a zero-based byte position. Offset 0 is the first byte. Writing a four-byte integer at offset 8 occupies offsets 8, 9, 10, and 11. The next free offset is 12.

Offset example

JavaScript
const message = Buffer.alloc(16);
message.writeUInt32BE(0, 8);  // bytes 8..11
message.writeUInt32BE(123, 12); // bytes 12..15
✓
Most protocol bugs are offset bugs

Before coding a binary message, write a layout table containing offset, size, type, and meaning. Add the sizes cumulatively. The announce request chapter follows this method.

3.11 64-bit values and BigInt

JavaScript Number cannot exactly represent every 64-bit integer. Modern JavaScript has BigInt, written with an n suffix. Node Buffer supports reading and writing 64-bit BigInt values.

The UDP tracker protocol ID

JavaScript
const b = Buffer.alloc(8);
const protocolId = 0x41727101980n;
b.writeBigUInt64BE(protocolId, 0);
console.log(b.toString('hex')); // 0000041727101980

This replaces the old tutorial's manual split into two 32-bit halves and replaces the native bignum package used for torrent sizes.

3.12 Buffer practice

1. Create a 6-byte Buffer.

2. Write IPv4 bytes 127, 0, 0, 1 at offsets 0-3.

3. Write port 6881 as a big-endian unsigned 16-bit integer at offset 4.

4. Read the port back and convert the first four bytes into 127.0.0.1.

One compact IPv4 peer entry

JavaScript
const peer = Buffer.alloc(6);
Buffer.from([127, 0, 0, 1]).copy(peer, 0);
peer.writeUInt16BE(6881, 4);

const ip = [...peer.subarray(0, 4)].join('.');
const port = peer.readUInt16BE(4);
console.log({ ip, port });
