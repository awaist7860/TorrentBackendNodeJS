13. Connect to peers, request blocks, and write the file

13.1 Top-level download state

The download function obtains peers, opens one output file, creates shared piece state, limits the number of simultaneous peer connections, and resolves when all blocks have arrived. A finally block always destroys sockets and closes the file descriptor.

State shared by all connections

JavaScript
export async function download(torrent, outputPath) {
  const peers = await getPeers(torrent);
  if (peers.length === 0) throw new Error('The tracker returned no peers.');

  const pieces = new Pieces(torrent);
  const fileDescriptor = fs.openSync(outputPath, 'w');
  const sockets = new Set();
  let finished = false;

  // Connect to up to 30 peers and wait for completion...
}

13.2 Pre-size the output file

Reserve the expected file length when safely representable

JavaScript
const totalSize = totalSizeBigInt(torrent);
if (totalSize <= BigInt(Number.MAX_SAFE_INTEGER)) {
  fs.ftruncateSync(fileDescriptor, Number(totalSize));
}

Pre-sizing is not required for positional writes, but it makes the intended output size visible immediately. fs APIs use Number offsets in this simple build, so the program avoids converting impossible-to-represent giant values.

13.3 Open a peer connection

One socket, one queue, one outstanding block

JavaScript
const socket = net.createConnection({ host: peer.ip, port: peer.port });
const queue = new Queue(torrent);
let inFlight = null;
let connectionError = null;

socket.setTimeout(30_000);

socket.on('connect', () => {
  socket.write(buildHandshake(torrent));
});

inFlight remembers the exact request currently assigned to this peer. Limiting each peer to one outstanding request makes the state easy to understand. Real clients pipeline many requests for speed.

13.4 Handle timeout, error, and close

Return abandoned work to the shared pool

JavaScript
socket.on('timeout', () => {
  socket.destroy(new Error('Peer connection timed out.'));
});

socket.on('error', (error) => {
  connectionError = error;
});

socket.on('close', () => {
  sockets.delete(socket);
  if (inFlight) pieces.markFailed(inFlight);
  peerFinished(connectionError);
});

13.5 Dispatch incoming messages

Only the messages needed for downloading

Text
switch (parsed.id) {
  case 0:
    queue.choked = true;
    break;
  case 1:
    queue.choked = false;
    requestNextBlock();
    break;
  case 4:
    queue.enqueuePiece(parsed.payload.readUInt32BE(0));
    requestNextBlock();
    break;
  case 5:
    addBitfieldToQueue(parsed.payload, torrent, queue);
    requestNextBlock();
    break;
  case 7:
    handlePiece(parsed.payload);
    break;
  default:
    break;
}

Unknown or unused message IDs are ignored in this small client. A production implementation would apply stricter extension negotiation and logging.

13.6 Request the next needed block

Fast peers naturally ask again sooner

JavaScript
function requestNextBlock() {
  if (queue.choked || inFlight || isFinished()) return;

  while (queue.length > 0) {
    const pieceBlock = queue.dequeue();

    if (pieces.needed(pieceBlock)) {
      pieces.markRequested(pieceBlock);
      inFlight = pieceBlock;
      socket.write(buildRequest(pieceBlock));
      return;
    }
  }
}

A queue item might already have been claimed by another connection since it was enqueued. pieces.needed checks the shared state immediately before sending. markRequested happens before socket.write so two synchronous callers cannot claim the same job in between those operations.

13.7 Validate the piece response

Do not write unexpected data

JavaScript
const matchesRequest =
  pieceResponse.index === inFlight.index &&
  pieceResponse.begin === inFlight.begin &&
  pieceResponse.block.length === inFlight.length;

if (!matchesRequest) {
  socket.destroy(new Error('Peer returned a block we did not request.'));
  return;
}

A peer controls every incoming byte. The response must match index, begin, and requested length. Closing a misbehaving connection triggers markFailed, so the block can be requested elsewhere.

13.8 Calculate the absolute file offset

Piece-relative begin -> whole-file offset

JavaScript
const offset =
  pieceResponse.index * torrent.info['piece length'] +
  pieceResponse.begin;

pieceResponse.begin starts at zero within its piece. Multiplying the piece index by the normal piece length finds the start of the piece in the logical file; adding begin finds the block position. This still works for the short final piece because every earlier piece has normal length.

13.9 Write the block

Positional write

Text
fs.writeSync(
  fileDescriptor,
  pieceResponse.block,
  0,
  pieceResponse.block.length,
  offset,
);
ArgumentMeaning
fileDescriptorThe open output file returned by fs.openSync.
pieceResponse.blockThe received data bytes.
0Start reading from byte 0 of the block Buffer.
block.lengthWrite all bytes in this block.
offsetPlace them at this absolute output-file position.

Synchronous positional writes are used deliberately to avoid closing the file while asynchronous writes remain pending. The peer sockets are already asynchronous, and the code prioritises clarity over maximum throughput.

13.10 Mark completion and continue

One block completed

Text
pieces.markReceived(pieceResponse);
inFlight = null;
process.stdout.write(`Progress: ${pieces.percentDone()}%\r`);

if (pieces.isDone()) {
  finishDownload();
} else {
  requestNextBlock();
}

13.11 Finish exactly once

Several sockets may notice completion-related events close together. finishDownload checks a shared finished flag, destroys all sockets, and resolves the outer Promise once. The finally block closes the file descriptor after the Promise settles.
