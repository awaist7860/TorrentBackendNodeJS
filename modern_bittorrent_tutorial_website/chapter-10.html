10. Peer message types and message builders

10.1 Common message framing

After the handshake, most peer messages begin with a four-byte big-endian length prefix. The prefix counts every byte after itself: one ID byte plus any payload. A keep-alive is the special case with a zero length and no ID.

IDNamePayload
-keep-aliveNo ID and no payload. Four zero bytes.
0chokeNone.
1unchokeNone.
2interestedNone.
3not interestedNone.
4have4-byte piece index.
5bitfieldOne bit for each piece, most-significant bit first within each byte.
6request4-byte index + 4-byte begin + 4-byte length.
7piece4-byte index + 4-byte begin + block bytes.
8cancelSame three integers as request.
9port2-byte DHT listen port; not used by this client.

10.2 One generic builder removes repetition

Generic length + ID + payload builder

JavaScript
function buildMessage(id, payload = Buffer.alloc(0)) {
  const buffer = Buffer.alloc(4 + 1 + payload.length);
  buffer.writeUInt32BE(1 + payload.length, 0);
  buffer.writeUInt8(id, 4);
  payload.copy(buffer, 5);
  return buffer;
}

The old tutorial repeated the allocation and prefix code for every message. A helper is easier to audit: the allocation includes four prefix bytes, one ID byte, and the payload; the stored length excludes the four-byte prefix.

Simple control messages

export function buildKeepAlive() {

export function buildUnchoke() { return buildMessage(1); }

10.4 have and bitfield

Availability messages

JavaScript
export function buildHave(pieceIndex) {
  const payload = Buffer.alloc(4);
  payload.writeUInt32BE(pieceIndex, 0);
  return buildMessage(4, payload);
}

export function buildBitfield(bitfield) {
  return buildMessage(5, bitfield);
}

The original article's buildBitfield function referred to payload even though the parameter was named bitfield. The generic helper removes that error and allocates the correct variable length.

10.5 request, piece, and cancel

Block messages

JavaScript
export function buildRequest({ index, begin, length }) {
  const payload = Buffer.alloc(12);
  payload.writeUInt32BE(index, 0);
  payload.writeUInt32BE(begin, 4);
  payload.writeUInt32BE(length, 8);
  return buildMessage(6, payload);
}

export function buildPiece({ index, begin, block }) {
  const payload = Buffer.alloc(8 + block.length);
  payload.writeUInt32BE(index, 0);
  payload.writeUInt32BE(begin, 4);
  block.copy(payload, 8);
  return buildMessage(7, payload);
}

export function buildCancel({ index, begin, length }) {
  const payload = Buffer.alloc(12);
  payload.writeUInt32BE(index, 0);
  payload.writeUInt32BE(begin, 4);
  payload.writeUInt32BE(length, 8);
  return buildMessage(8, payload);
}

10.6 Parse a complete message

Correctly parse integer length fields

JavaScript
export function parseMessage(message) {
  if (message.length < 4) throw new Error('Peer message is too short.');

  const size = message.readUInt32BE(0);
  if (message.length !== size + 4) {
    throw new Error('Peer message length prefix does not match its data.');
  }

  if (size === 0) return { size, id: null, payload: null };

  const id = message.readUInt8(4);
  const rawPayload = message.subarray(5);
  let payload = rawPayload;

  if (id === 6 || id === 8) {
    if (rawPayload.length !== 12) throw new Error('Invalid request payload.');
    payload = {
      index: rawPayload.readUInt32BE(0),
      begin: rawPayload.readUInt32BE(4),
      length: rawPayload.readUInt32BE(8),
    };
  } else if (id === 7) {
    if (rawPayload.length < 8) throw new Error('Invalid piece payload.');
    payload = {
      index: rawPayload.readUInt32BE(0),
      begin: rawPayload.readUInt32BE(4),
      block: rawPayload.subarray(8),
    };
  }

  return { size, id, payload };
}

The older parser stored the remaining four bytes as length for request/cancel instead of reading them as an integer. The modern parser validates exact payload lengths and uses readUInt32BE.
