9. TCP, the peer-wire protocol, and the handshake

Basic peer connection shape

9.1 A TCP socket in Node.js

Basic peer connection shape

JavaScript
import net from 'node:net';

const socket = net.createConnection({ host: peer.ip, port: peer.port });

socket.on('connect', () => {
  console.log('Connected');
});

socket.on('data', (bytes) => {
  console.log(`Received ${bytes.length} bytes`);
});

socket.on('error', console.error);
socket.on('close', () => console.log('Closed'));

TCP gives an ordered stream of bytes. It does not preserve the message boundaries used by the BitTorrent application protocol. Chapter 11 builds a framing function to solve that.

9.2 The peer-wire conversation

1. Connect to the peer's IP address and port.

2. Send a BitTorrent handshake containing our torrent info hash and peer ID.

3. Receive and validate the peer's handshake.

4. Send interested.

5. Read choke/unchoke and piece-availability messages.

6. When unchoked, send request messages for blocks the peer has.

7. Receive piece messages and write their block bytes into the output file.

9.3 Handshake layout

OffsetSizeFieldValue
01pstrlen19
119pstrASCII/UTF-8 text BitTorrent protocol
208reservedAll zero in this basic client.
2820info_hashSame raw hash sent to the tracker.
4820peer_idOur process peer ID.

The standard v1 handshake is 68 bytes because 1 + 19 + 8 + 20 + 20 = 68.

9.4 Build the handshake

Handshake builder

JavaScript
const PROTOCOL_NAME = 'BitTorrent protocol';
const PROTOCOL_NAME_BUFFER = Buffer.from(PROTOCOL_NAME, 'utf8');
 
export function buildHandshake(torrent) {
  const buffer = Buffer.alloc(68);
 
  buffer.writeUInt8(PROTOCOL_NAME_BUFFER.length, 0);
  PROTOCOL_NAME_BUFFER.copy(buffer, 1);
  // Buffer.alloc already made reserved bytes 20-27 zero.
  infoHash(torrent).copy(buffer, 28);
  getPeerId().copy(buffer, 48);
 
  return buffer;
}

9.5 Parse the peer handshake

Handshake parser

JavaScript
export function parseHandshake(buffer) {
  if (buffer.length < 49) {
    throw new Error('Handshake is too short.');
  }

  const protocolLength = buffer.readUInt8(0);
  const expectedLength = 49 + protocolLength;

  if (buffer.length !== expectedLength) {
    throw new Error('Handshake has an invalid length.');
  }

  const protocol = buffer.toString('utf8', 1, 1 + protocolLength);
  const infoHashStart = 1 + protocolLength + 8;

  return {
    protocol,
    infoHash: buffer.subarray(infoHashStart, infoHashStart + 20),
    peerId: buffer.subarray(infoHashStart + 20, infoHashStart + 40),
  };
}

The parser does not assume pstrlen is 19 while finding offsets; it derives the positions from the first byte. The caller still checks that the protocol text equals BitTorrent protocol and that the returned info hash equals the expected torrent hash.

9.6 Why validate the info hash

A TCP connection can reach the wrong process, a malicious peer, or a peer that closes/reuses a port. Matching the info hash proves that the peer says it is discussing the torrent we requested. Buffer.equals compares the raw 20 bytes.
