6. UDP, dgram, tracker URLs, and the two-request flow

How node:dgram feels

6.2 A minimal UDP example

How node:dgram feels

JavaScript
import dgram from 'node:dgram';

const socket = dgram.createSocket('udp4');

socket.on('message', (message, remote) => {
  console.log(`Received ${message.length} bytes from ${remote.address}`);
});

socket.on('error', (error) => {
  console.error(error);
  socket.close();
});

socket.send(Buffer.from('hello'), 9999, '127.0.0.1');

send transmits one datagram. message events deliver replies. UDP itself does not promise that a reply will arrive, so our tracker code adds timeouts and retries.

6.3 Parse a tracker URL

The current URL API

JavaScript
const trackerUrl = new URL('udp://tracker.example.org:6969/announce');
console.log(trackerUrl.protocol); // udp:
console.log(trackerUrl.hostname); // tracker.example.org
console.log(trackerUrl.port);     // 6969

The old tutorial used url.parse. new URL returns a structured URL object. The port property is text, so Number(trackerUrl.port) converts it before dgram.send.

6.4 Why UDP trackers use connect then announce

BEP 15 defines two main exchanges for our purpose. The connect request proves that a client can receive packets at its apparent source address and gives it a temporary 64-bit connection ID. The announce request then uses that connection ID and asks for peers for one torrent.

ExchangeClient sendsTracker returns
ConnectProtocol ID, action 0, random transaction ID.Action 0, matching transaction ID, 8-byte connection ID.
AnnounceConnection ID, action 1, transaction ID, info hash, peer ID, transfer counters, event, options, port.Action 1, matching transaction ID, interval, leechers, seeders, compact peers.

6.5 Transaction IDs

A transaction ID is a random 32-bit value copied into a request. The tracker copies it into the response. This lets the client ignore unrelated packets and match a response to the correct request.

Cryptographically random four-byte value

JavaScript
export function randomUInt32() {
  return crypto.randomBytes(4).readUInt32BE(0);
}

6.6 Retries

BEP 15 recommends retransmitting after 15 * 2^n seconds. The first waits 15 seconds, the next 30, then 60, and so on. This guide tries three times by default. A timeout is expected network behaviour, not necessarily a code exception.
