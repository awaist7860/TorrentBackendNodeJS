1. What BitTorrent is and what this client will do

1.1 The simple mental model

A normal web download usually asks one server for one file. BitTorrent divides a file into numbered pieces and lets many computers exchange those pieces. A computer participating in the same torrent is called a peer.

✓
The two halves of this project

First, ask a tracker for peer addresses. Second, connect directly to those peers and request file blocks. The tracker does not normally send the file itself.

StepActionMeaning
1Read the .torrent fileLearn the tracker address, file name, size, piece size, and the expected SHA-1 hash for every piece.
2Contact a trackerSend the torrent info hash and receive IP address + port pairs for peers.
3Open TCP connectionsConnect directly to a selection of peers.
4HandshakeProve that both sides are talking about the same torrent.
5Learn what each peer hasProcess have and bitfield messages.
6Request blocksAsk an unchoking peer for a block within a piece.
7Write blocks at exact offsetsPlace each received block in the correct position in the output file.
8FinishStop when every expected block has been received.

1.2 Tracker, peer, seeder, leecher, piece, and block

TermBeginner meaning
TrackerA coordination service. It tells clients where peers may be found.
PeerAnother BitTorrent client connected to the same torrent swarm.
SeederA peer that has all of the torrent data.
LeecherA peer that is still downloading. It may also upload pieces it already has.
SwarmAll peers participating in one torrent.
PieceA fixed-size region of the torrent data, except the final piece may be shorter.
BlockA smaller request-sized region inside a piece. This guide uses 16 KiB blocks.
Info hashA 20-byte SHA-1 identifier made from the bencoded info dictionary in a v1 torrent.
Peer IDA 20-byte identifier for one running client instance.

1.3 Why the project is educationally useful

  • You work with real binary protocols rather than JSON-only APIs.
  • You learn TCP and UDP differences through code.
  • You practise asynchronous events, buffers, offsets, hashing, files, queues, and tests.
  • You see why network code must validate lengths and identifiers instead of trusting input.
  • You build a larger project from small modules instead of putting everything in index.js.

1.4 What happens on the wire

Most values in BitTorrent protocol messages are not sent as readable text. They are bytes with agreed positions and sizes. For example, a four-byte unsigned integer may occupy bytes 8 through 11 of a message. Both sides must agree that those four bytes mean the same thing.

A five-byte peer message shown in hexadecimal

Text
00 00 00 01  02
^^^^^^^^^^  ^^
length = 1 id = 2 (interested)

The first four bytes are the big-endian integer 1. That says one byte follows the length prefix. The next byte has value 2, which means interested.
