About this guide

This guide keeps the learning path and subject coverage of the original tutorial, but rewrites the code for a current Node.js environment and explains the missing background topics in one place. It is deliberately slower and more detailed than a normal programming article.

i
What you will build

A small command-line BitTorrent v1 downloader that reads a .torrent file, contacts a UDP tracker, connects to peers over TCP, requests blocks, and writes a single output file. It is a learning client, not a production replacement for qBittorrent, Transmission, or similar software.

Scope and deliberate limitations

  • BitTorrent v1 metainfo only. BitTorrent v2 and hybrid torrents use additional rules and SHA-256 based structures.
  • Single-file torrents only. Multi-file layout is explained as an extension.
  • UDP trackers only. HTTP/HTTPS trackers, DHT, PEX, LSD, magnet links, and WebRTC are outside the core build.
  • IPv4 compact peer lists only. IPv6 compact peers use a different representation.
  • Download-only. This client does not upload pieces or participate as a full seeder.
  • One outstanding block per peer. This is intentionally simple, but slower than request pipelining.
  • The final learning build does not yet verify each completed piece hash before accepting it. The integrity upgrade is explained in the improvements chapter and should be implemented before treating the program as robust.
!
Legal and network safety

Use a small, legal test torrent. Public peer IP addresses are untrusted input. Run this code as a normal user, not as an administrator, and do not open an inbound router port for this tutorial.

How to use the guide

  1. Read Chapters 1-4 before coding. They explain the protocol, Buffer objects, byte order, and bencoding.
  2. Create the project in Chapter 5 and add each file in order.
  3. Run npm test after the protocol-building chapters. Byte-level bugs are easier to fix before trying a live tracker.
  4. Use the full source listings in Appendix A to compare your files.
  5. Use the troubleshooting chapter when a tracker or peer fails. A failure does not always mean your code is wrong; public trackers and peers come and go.
